Velora Flow Analytics

How the wizard records each patient's path through the quiz: when each step starts and stops, where people leave, who comes back, and what gets submitted. Everything is driven by the step ids in wizard-a.json / wizard-b.json; nothing is hard-coded per step.

How it works

One Firestore document per person, created the first time the wizard loads. The session id lives in the browser next to the saved answers, so a reload or a later visit on the same device continues the same document.

flowchart TD
  L([Page load]) --> Q{Saved session and step above 0?}
  Q -- no --> N[New doc: status in_progress]
  Q -- yes --> R[Same doc: resumes +1]
  N --> S[start: visits +1, lastStart]
  R --> S
  S --> X{Person leaves the step}
  X -- Next, auto-advance or Back --> T[stop: lastStop, totalMs += time]
  X -- closes the tab --> E([No stop = exit on this step])
  T -- next step is not confirmation --> S
  T -- next step is confirmation --> U[submit: answers, status submitted]

What it answers

QuestionHow to read it
ConversionDocs with status: "submitted" ÷ all docs.
Where people leaveFor in_progress docs, the step where lastStart has no later lastStop. Count per step id.
Which steps cause frictionMedian totalMs per step id. A long time on a one-tap step means unclear copy or a hard question.
Where people hesitatevisits > 1 means they came back to that step with Back or after a resume.
Does resume matterShare of submitted docs with resumes > 0.
Which config converts betterSplit every metric by variant.
Before / after a changeSame reads, split by createdAt around a release.

Because the keys are the step ids from wizard-a.json / wizard-b.json, adding, merging or removing steps needs no code change. New ids simply appear in new docs.

Before real patients

  • Health data. answers holds health and contact details, special-category data under GDPR. Add consent copy and send answers through a server function rather than straight from the browser.
  • Open write rule. Firestore rules let anyone create or update a sessions doc, never read or list one. Add App Check or anonymous auth so only the real app can write.
  • Abandon window. Decide when an open session counts as abandoned (for example 30 minutes without updatedAt), so in-progress and lost can be told apart.
  • Clock. lastStart and lastStop are device time, which is fine for durations but not for ordering across devices.
